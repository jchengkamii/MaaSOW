# 通用行军单元

由业务功能决定目标；通用单元不搜索怪物或玩家，不自动调节弟子数量。
复用已有大世界、内城识别和返回模板，进入大地图后点击目标。

```python
from agent.custom.action.march.march import March

# 调用方持有 AutomationMutex（普通 case 的 worker 已持有）。
march = March(engine)
handle = march.dispatch(target=(360, 600), queue=2)
march.wait(handle, timeout=900, poll_interval=0.5)
```

target 使用 Maa 归一化截图坐标。需要业务导航时可用
`march.dispatch(None, queue=1, select_target=lambda engine: ...)`；
回调在确认大地图后执行，负责选择目标并打开环形菜单。
队列编号 1–4，省略时使用气泡指向的当前队列；锁、月卡及无法确认编号的槽位不点击。
一键上阵只点击一次，重新识别出征按钮后派遣。

出征人数通过人数条左侧图标定位，只读取同一帧中图标右侧、同一行的有效人数分数，不依赖“弟子数量”标题。图标模板 `Common/March/disciple_count_icon.png` 来自本地保存的貔貅出征面板截图。人数栏短暂不可读时，最多重新截图读取 8 次，失败之间间隔 0.5 秒；不凭地图上的其他分数放行。人数为 0 时禁止出征，持续无法确认时保存失败原图并停止。提交标记仅在实际点击出征或组队时设置，点击前的识别失败不会进入已提交队伍的恢复确认。

`dispatch` 返回已确认出征的句柄；`poll(handle)` 单次判断完成；
`wait(handle)` 等待完成或超时。可以保存多个句柄轮询，不要并发操作同一游戏 UI。
兼容 case 的入口为 `agent.custom.action.march.march:run`，参数为
`target: [x, y]`、`queue: 1..4`（可省略）、`timeout: 900`、`poll_interval: 0.5`。
当前是公共单元，未添加缺少目标配置的前台任务。

仅从小队行上半部分 OCR 前往、战斗中、返回，倒计时不进入状态 OCR 图片。
按头像跟踪队伍，列表重排不改变身份。先看到返回，再连续 3 次确认头像消失、
队列数减少才结束；列表收起、遮挡、识别失败和头像歧义不会判为结束。
点击出征后未确认队伍会报错，不重放出征；体力不足等弹窗由调用方处理。
同头像队伍不能区分时保守等待，超时报错。适用项目短边 720 的竖屏布局。

行军使用独立的 `model/ocr/march_zh` 中文模型；保留原有英文数字模型。
源模型来自同级 MaaFramework 测试资源，来源见模型目录 README。
出征前会读取已有小队，拒绝与所选队伍同头像的已有行军，防止把旧队列当成新出征。

每次确认出征后，按队号保存出征面板与大世界小队栏的头像对应关系。空闲判断、出征确认和异常复核优先使用已确认的大世界头像，避免两个界面的缩放、裁剪差异导致误判。每次复用先核对面板头像，头像变化时丢弃旧记录；首次出征仍使用原有的唯一新增队伍或头像匹配确认规则。

已经打开出征面板时，可用 `handle = march.dispatch_from_panel(queue=1)` 直接续接，
随后调用 `march.wait(handle)`。若调用方有出征前小队快照，可传 `existing=rows` 检查头像冲突。
进攻菜单使用文字定位后匹配上方红色图标，点击图标而非文字。


所有使用出征面板的功能都继承 `March`，通过 `dispatch()` 或 `dispatch_from_panel()`
进入共享的 `DispatchPanel` 流程：等待动画、确认目标后补点入口、处理自动补体、
复核空闲队列和旧占用记录、稳定确认切队、检查弟子数量、确认唯一新增行军队伍。
提交结果不明确时只恢复界面并核对对应队伍，不再次提交；仅明确的体力不足提示
允许补体后重试。任务计数由业务层根据确认出发或完整返回规则决定。
补体按钮的检查、首次点击和后续点击均覆盖下半屏全宽，兼容组队面板向左或向右展开，避免检查能识别而实际点击节点裁掉按钮。

大地图搜索入口统一使用 `open_world_search()`；原图匹配失败时只匹配放大镜内部图形，
模板位于 `Common/March/`。调用方继续负责页签、等级和目标选择。
行军的大地图默认态由左下搜索图形和右下回宗门控件同时确认，均限制在对应底部区域，不依赖内城共用的“长老”标签。玲儿启动或通用派遣入口无法确认大地图时也保存现场截图，避免只报告入口超时而丢失实际界面。

只读返回复核统一调用 `confirm_idle_in_panel(handle, select_target=定位回调, keep_open=False)`，
定位、打开面板、补体后的重新定位及失败恢复均在同一异常处理范围内。
随后通过 `ready_dispatch_panel()` 至少两帧核对队号、占用和派遣前头像；
它只返回复核结果，不派遣、不修改任务计数。重试次数及进入复核的条件由任务决定。
需要直接继续派遣时传 `keep_open=True`，保留面板和派遣前小队快照。
`panel(image)` 是单帧识别接口，业务流程不要用它代替面板准备和恢复。
目标任务提供 `target_dispatch_point(image)` 和 `target_tooltip_pattern`，以及
`dispatch_caption`（出征或组队）；通用入口要求图标连续三帧稳定。
识别失败的原始截图保存在 `debug/<任务名>_panel_failure.png`。

状态行图标全部或部分漏检时，通用行军会按同尺寸截图中已确认的行位置补读漏检行。小队数量变化时也逐行复核，只有漏检行头像相似度至少 0.80、状态文字可解析且不会重复匹配已定位头像时才恢复该行；明确识别到“采集中”也可以恢复该行，但不作为出发、战斗或返回证据。完整列表必须与当前可靠识别的小队数量一致，不沿用缓存数量。补读仍不足以确认完整列表时，只接受可见队伍的正向状态证据，不据此判断队伍消失或完成。不会仅凭数量或集结后消失推断完成。补读失败的当时原图另存为 `debug/<任务名>_row_recovery_failure.png`，最多每 10 秒更新一次，不被后续面板失败截图覆盖。

小队数量首先只读取标题栏最右侧，排除左侧蓝色行军箭头；每次 OCR 都要求完整分数，避免把 `>0/4` 这样的混合结果当成成功而跳过后续读法。窄区域识别失败时，在左上小队区域重新检测完整分数，只接受“小队”标题同一行、右侧固定数量栏内唯一的 `0/4` 等有效分数。不会把 `214` 猜成 `2/4`，也不接受地图其他位置出现的分数；完整列表仍需数量与确认的队伍行一致。

数量栏被地图文字干扰时，提交确认和恢复确认允许使用唯一队伍行作为正向证据：头像相似度至少 0.80、状态符合出征或组队类型，并连续三帧确认。此兜底不用于判断队伍消失或完成次数；这些判断继续要求完整列表可靠。
